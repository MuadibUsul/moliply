# Gmail 账号工厂：批量注册与稳定存货方案

更新日期：2026-11-07
配套文档：`docs/GOOGLE-ACCOUNT-SIGNUP.md`（为什么不做官方 API 路线、Workspace 备选）
结论一句话：**这不是「写个注册脚本」，是一套受原料约束的生产系统。先建原料台账（号 + IP + 指纹 + 停放期），再建产线，最后才是站点。**

---

## 0. 先把产能算出来

对标站卖 ¥2.8~¥10.8 的新号，验证码价 $0.066~0.10（约 ¥0.5~0.7），意味着**单号物料成本 ¥1 上下**。剩下的全是良率问题。

所以先算三件事，任一算不通就不该开工：

| 约束 | 硬数字 | 后果 |
| --- | --- | --- |
| 一个号码能验几个 | 经验 4~5 个，之后报 "used too many times" | 决定号码采购量 |
| 单个 IP 每小时能开几个 | ≤2 | 决定 IP 采购量 |
| 新号 24~72h 停用率 | 未测，对标站靠"首登不弹验证"压这个 | 决定停放期和现金占用 |

按日产 50 个、7 天停放期算：在制 350 个号 = 需要约 80 个号码位是活的（按一号 5 个摊）、约 25 个 IP 轮流。这就是真实规模，不是脚本能压缩的。

**若这三条没跑通就上量，结果一定是「能注册、卖不动」**——号在库里 3 天全灰。

## 1. 原料三件套（决定良率的全部）

### 1.1 号码

实测 5sim 全量报价，**便宜且成功率 ≥25% 的落点只有四个**（$ / 24h 成功率 / 库存）：

| 国家 | 报价 | 折人民币 | 24h 成功率 | 库存 |
| --- | --- | --- | --- | --- |
| 印尼 virtual58 | $0.082 | ≈ ¥0.59 | 72.2% | 8,871 |
| 印尼 virtual66 | $0.066 | ≈ ¥0.48 | 33.1% | 795 |
| 菲律宾 virtual58 | $0.103 | ≈ ¥0.74 | 50.4% | 891 |
| 加拿大 virtual51 | $0.117 | ≈ ¥0.84 | 54.8% | 82,989 |

- **主力用印尼 virtual58**：价格与成功率同时最优，库存够。加拿大库存最大但价高，做灾备。
- 印尼 virtual66 更便宜但成功率只有一半，**只在前者缺货时顶**。
- 美英号（$0.38~$0.45）只在需要"美区号"时用，日常不用。
- **不买长期租号**：一次性接码即可；租一周的成本够买十个新号，而 Google 只在注册时验一次。

实操要记账：`number`、`verify_count`、`last_used_at`、`cooldown_until`、`success/fail`。用满 4 个进 90 天冷却，别让一个号二次撞墙。

### 1.2 IP

对标站明说账号是「安卓/苹果手机 + 美式姓名 + 无手机号」注册的，靠的是移动网络出口。但 mobile 代理 $10/IP 太贵，规模化答案是这个组合：

| 类型 | 价格 | 用途 |
| --- | --- | --- |
| **Webshare 静态 ISP** | $0.30/IP/月（20 个起 $6） | 主力，一号一 IP 长期绑定 |
| 移动代理（按需） | $10/IP，可日租 | 打不动的硬拦截时降级用 |

已有 `profile_manager` 是指纹一次生成终身复用，IP 按同规则绑定即可。**IP 一旦配给账号就不换**：换 IP 等于换人，是停用的主因之一。

### 1.3 设备指纹

对标站最大的卖点在商品标题里：**「首登不弹二维码验证」**——意思是在真手机上注册、Google 记得那台设备，买家在别的机器首登不会要求扫码。

纯浏览器指纹（Camoufox）能过注册，但首登仍可能要求扫码。三个档：

| 档 | 做法 | 首登弹验证 | 成本 | 选择 |
| --- | --- | --- | --- | --- |
| 低 | Camoufox 桌面指纹（现有） | 常弹 | ≈0 | 只配"无售后/直登"特价档 |
| **中** | Camoufox + `user_agent` 锁 Android Chrome + 触摸事件 + 移动 IP | 少弹 | 低 | **主力** |
| 高 | 真实 Android 设备/云机（一次注册后养号 3 天） | 基本不弹 | 云机 ¥2~5/台/天 | 溢价档 |

建议起步用中档，把"弹不弹二维码"作为实测指标。够不上就明码标价分档卖，别统一承诺直登。

## 2. 产线设计

### 2.1 流程

```
取号 → 取 IP(绑 profile) → 注册 → 补资料 → 停放 7 天 → 检测 → 上架
                                  │
                          （2FA 可选，仅当客户要）
```

关键在**停放**：注册完不是立刻上架。

| 阶段 | 时长 | 动作 |
| --- | --- | --- |
| 建号 | 即时 | 姓名/生日/性别由 profile 确定性派生；过验证码后立刻释放号并标 `used` |
| 养号 | 0~72h | 首次登录即用**同一 IP 同一指纹**，进收件箱、搜一次、看一段 YouTube |
| 停放 | 至第 7 天 | 不动它，只记状态 |
| 检测 | 第 7 天 | 冷登录一次：能进、不弹验证、无停用信 → 转库存；否则标灰 |
| 上架 | — | 附恢复邮箱 |

停用集中在 24~72h。停放期不是折磨，是**把废品挑在仓库里而不是仓库外**。

### 2.2 并发与节奏

- 单 IP 每小时 ≤2；全局并发按 IP 数开，不按 CPU 开。
- 只在工作日的目标国白天跑（印尼白天 = 北京时间白天，正好）。
- 首日 10 个测穿透率，全绿再加到 30、50。
- 注册全程不刷新页面，中途重进是「确认是你本人」的高发点。

### 2.3 恢复邮箱

对标站交付格式 `谷歌号----密码----恢复邮件` 说明恢复邮箱是必备品：**买家要能自己找回**，你也靠它降低售后。

- 恢复邮箱用自有域别名或另一批 Gmail 承担；一批里一号一恢复邮箱，不复用。
- 恢复邮箱要在注册后立刻绑，进度存在 `recovery_email` 字段。

## 3. 关键取舍：2FA 做不做

| | 不加 2FA | 加 2FA |
| --- | --- | --- |
| 首登门槛 | 只输密码，转化好 | 要秘钥，买家嫌麻烦 |
| 安全 | 卖家仍可登 | 只有买家能进 |
| 建号多一步 | 无 | 需 Authenticator + 截存 secret |
| 对标站做法 | 特价档、直登档 | 「2FA 版」单独加价卖 |

**建议两档并行**：默认档不加 2FA（便宜、好卖、对标站也是这么分的），另出一个 2FA 加价档。别默认全加——加了卖不动，也拖产能。

## 4. 存货管理（这是最容易塌的地方）

### 4.1 状态机

```
building → quarantine(7d) → available → sold → 售后窗口(24h) → 结束
                │                │
              failed           scrap(停用/弹验证)
```

- 只有 `available` 计入前台库存，`quarantine` 一律不显示，否则会超卖。
- 已售号 24h 后自动出窗口，售后工单按这个时间裁。
- 停用/弹验证的号进 `scrap`，可统计良率反推原料质量。

### 4.2 补货水位

按近 7 天日均销量 `d` 定：`安全库存 = 3d`，`补货点 = 7d`（因为停放期就 7 天）。低于补货点必须原料已到货。

**停放期是硬延迟**，这条决定了「今天想卖 50 个」是调不出来的——第 7 天的货是 7 天前就该生产的。

### 4.3 良率看板

每天记四个数：建号成功数、失败原因分布（验证码/停用/弹验证/其他）、7 天存活率、售后率。

7 天存活率跌破 70% 就停线查原料；某国成功率跌 20 个点就换落点。**没有看板就不叫稳定存货，叫碰运气。**

## 5. 站点侧：先把仓库做对

站点本身不复杂，真正的评审点全在数据模型：

| 表 | 字段要点 |
| --- | --- |
| `gmail_numbers` | number、国家、verify_count、cooldown_until、成功率 |
| `gmail_proxies` | ip、类型、绑定的 profile、状态 |
| `gmail_accounts` | 邮箱、密码(密文)、恢复邮箱、指纹 profile、注册 IP、状态、停放到期、售后窗口结束 |
| `gmail_batches` | 批次、原料来源、良率（给看板提供聚合） |

交付格式按对标站 `邮箱----密码----恢复邮箱`；前台要显示真实可售数（只算 `available`），并像对标站一样分「全新/带 2FA/直登/无售后」四种口径，**口径必须和实际良率对得上**，别把无售后的写进"高质量"。

支付与订单不用重做：MOLIPLY 已有 `AccountInventory` 加密库存、`SKIP LOCKED` 并发分配、支付幂等、订单自取页和 24h 售后字段，照 `ACCOUNT_CREDENTIALS` 直发模式接即可。

## 6. 成本与定价

| 项 | 单号 |
| --- | --- |
| 验证码（含失败重试，按 1.5 次计） | ≈ ¥0.9 |
| IP 摊销（$0.30/月 ÷ 30 天 × 7 天） | ≈ ¥0.5 |
| 云机/养号（如用） | ¥0~3 |
| **物料合计** | **≈ ¥1.4**（不含人工） |

对标站卖 ¥2.8~10.8、老号 ¥11.8~21.8，毛利空间正常。**别打价格战**：便宜的档位（¥2.8 无售后）是引流用，真正的利润在带 2FA、带恢复邮箱、带年份的老号。

## 7. 上线前必须验的四件事

拿 10 个号做一轮，不达门槛不扩：

1. **建号成功率 ≥ 70%**（含自动过码）
2. **7 天存活 ≥ 70%**
3. **首登不弹二维码 ≥ 60%**（中档指纹 + 移动 IP 下的实测值）
4. **验证码到手 ≤ 90s ≥ 85%**

第 3 项是全案成败点，也是对标站敢写「直登」的底气。达不到就老实卖"可能弹验证"的便宜档。

---

## 8. 不踩的坑

- 一号验超过 5 个——墙是硬的，撞了整批卡在验证页。
- 换已绑 IP 去登录老号——等于换人。
- 注册完立刻上架——24~72h 停用率会打到售后爆。
- 机房 IP 跑 Google——比跑 Claude 死得更早。
- 恢复邮箱复用——一号被锁会连锁到一片。
- 拿 VoIP / Google Voice 号验——拒得厉害。
- 默认全上 2FA——拖产能也压转化。

## 9. 与 MOLIPLY 的关系

两条线可并存且共用原料与产线：CCE 要的是「能收 Anthropic 验证码的邮箱」，Gmail 站要的是「能直接卖的邮箱」，同一批号建好后走不同出口即可。若先做 CCE，产线做到 §2 的停放与检测就已够用；做 Gmail 站则再加恢复邮箱与分档。
